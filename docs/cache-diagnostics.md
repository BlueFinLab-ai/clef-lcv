# Cache diagnostics

`GET /cache/diagnostics?after=0&limit=512` returns CPU RAM and GPU VRAM prefix inventories, a read-only RAM budget sample, and recent cache events. It uses the same authentication as `/health`; responses are marked `no-store`. `limit` is 1–512. Follow `telemetry.next_cursor` to read later events. `cursor_gap` means older events have expired from the bounded ring.

`CLEF_CACHE_TELEMETRY_EVENTS` controls ring capacity (default 2,048; 0 disables event storage). Aggregate action/reason counters remain available under `/health` → `optimizations.prefix_cache.telemetry`. No prompt text, token IDs, source IDs, image URLs or credentials are stored in diagnostics. Entry keys are salted fingerprints, consistent across CPU/GPU tiers within one service process; they change after a restart.

Single-request responses add `usage.cache_trace` with a request ID and first/last event numbers. Nested interleaved requests have independent IDs; filter events by ID, rather than assuming every event between those numbers belongs to that request. Batched forwards currently expose aggregate cache events without per-row attribution.

Events cover lookup, admission, duplicate writes, hits, restore rejection, clear and eviction. CPU admissions report logical checkpoint bytes and incremental retained bytes. CPU evictions report actual bytes released, which can differ from logical size when immutable storage is shared. Evictions identify byte budgets, entry limits, active context workspace or the shared RAM budget. GPU evictions report whether a CPU copy was retained. CPU hit events report restore time; this synchronous interval includes device-copy setup and transfer, not pure PCIe bandwidth.

Inventory contains token counts, logical bytes, use counts and ages. It is capped at 256 entries per tier; `truncated` identifies incomplete inventories. An idle inference lock is required to inspect mutable banks. While inference is active, the endpoint returns the last idle inventory (or no inventory before the first idle sample), with `snapshot_status=last_idle_busy`; the event feed remains current. Reading diagnostics never evicts entries or changes admission limits.

`uses` is the lifetime reuse count; `eviction_frequency` is the current aged score. CPU prefix and processed-image caches use the lowest score, then least recent actual access. Scores halve and round down every 900 seconds by default, calculated lazily. Configure `CLEF_CACHE_FREQUENCY_DECAY_SECONDS` or `--cache-frequency-decay-seconds`; `0` restores lifetime LFU. Health exposes the active policy and interval under the two cache tiers. Transfers and diagnostic reads do not reset aging; entries are not expired merely because their score reaches zero.

RAM capacity is service-local: available RAM plus this service's retained/pending cache allocations, minus its reserve fraction. It is not 75% of total installed RAM. Other processes and cgroup limits reduce the budget. Swap is excluded. To troubleshoot a working set, replay identical requests, map their admission keys, then inspect which keys are still in either tier before repeating. A cache hit can still incur CPU-to-GPU restoration and decision processing; it does not guarantee an instantaneous or faster entire application query.
